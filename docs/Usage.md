## 前端导航页

前端导航页对应设置面板中的“外观”和“功能”区域，用于控制服务展示、容器卡片、自动地址、分组、搜索和集成服务。

### 卡片设置

卡片设置用于调整导航卡片与卡片弹窗的外观、液态玻璃效果及状态信息。

可配置项：

- **卡片背景透明度**：调整导航卡片背景的透明程度。
- **卡片弹窗透明度**：单独调整卡片弹窗的透明程度。
- **卡片圆角**：调整卡片边角的弧度。
- **图标形状**：可选择圆形、圆角或方形。
- **液态玻璃**：为卡片及卡片弹窗增加背景折射与玻璃质感。
- **容器状态提示**：仅在容器卡片中显示，绿点代表正常运行，黄点代表异常或错误，红点代表已停止。
- **显示 CPU / 内存**：直接在导航页查看容器资源占用。
- **新增卡片默认位置**：选择新卡片放到最前或最后。

**液态玻璃效果**

开启后，卡片会透出背景并呈现玻璃折射效果，可按壁纸和阅读习惯调整以下选项：

- **液态玻璃背景模糊度**：调整卡片背后背景的模糊程度，范围为 0–20px；数值越大，背景细节越柔和。
- **弹窗液态玻璃模糊度**：单独调整卡片弹窗的背景模糊程度，范围为 0–20px。
- **液态玻璃强度**：调整玻璃折射效果的强弱，范围为 0–100%；数值越大，效果越明显。

::: tip 透明度与阅读体验
开启液态玻璃后，卡片背景透明度和卡片弹窗透明度固定为 0%，暂时不可调整；关闭后恢复原设置。背景较复杂时可适当增加模糊度，并降低玻璃强度，以保证文字清晰。
:::

![卡片设置 / 液态玻璃、透明度与状态提示](/assets/wiki/card-settings-v2.png)

### 背景设置

背景设置用于调整导航页整体视觉。

可配置项：

- 上传背景图。
- 可通过 URL 地址下载背景。
- 背景模糊。

::: tip 桌面端与移动端背景
桌面端和移动端背景需分别上传、单独设置，以适配不同屏幕比例。建议桌面端使用横向图片，移动端使用竖向图片，减少裁切并保持主体完整。
:::

建议背景不要过亮或过花，否则会影响卡片和文字识别。

### 页面设置

页面设置用于调整浏览器与桌面图标、导航页布局、抽屉栏外观、Dashboard 显示内容、滚动方式和页脚信息。

**浏览器桌面图标**

可选择黑底 DP、白底 DP，或从图标库选择自定义图标，用于浏览器图标及添加到主屏幕时的图标，保存设置后生效。已添加的桌面图标可能被系统缓存，更换后如未更新，可删除原快捷方式并重新添加。

页面样式可调整：

- **页面最大宽度**：控制导航内容区域的最大展示宽度，适合不同分辨率屏幕和大屏展示。
- **分组卡片底边距**：调整分组之间的纵向间距，让不同服务分组更容易区分。
- **系统状态大小**：控制顶部系统状态信息的展示比例。
- **抽屉栏透明度**：调整设置面板或抽屉区域的透明效果，让背景和面板层次更协调。

**抽屉栏液态玻璃**

独立于卡片液态玻璃，可单独开启，让设置抽屉呈现背景折射与玻璃质感。开启后可调整抽屉栏的液态玻璃模糊度和强度：模糊度越高，背景细节越柔和；强度越高，玻璃效果越明显。

::: tip 抽屉栏透明度
开启抽屉栏液态玻璃时，抽屉栏透明度固定为 35%，暂时不可调整；关闭后恢复原设置，不受卡片液态玻璃开关影响。
:::

Dashboard 显示配置可控制首页顶部内容：

- 显示标语。
- 显示时间。
- 显示搜索栏。
- 显示系统状态，点击标语或时间可切换系统状态展示。

滚动模式可选择：

- **整个页面滚动**：页面整体一起滚动，适合服务卡片较多、希望浏览完整页面的场景。
- **分组卡片滚动**：分组区域独立滚动，适合希望顶部信息保持稳定、只滚动服务卡片列表的场景。

页脚可填写备案信息、版权说明或其他自定义文字。不填写时导航页不会显示页脚；填写后可选择显示位置，例如底部居中。

![页面设置 / 浏览器图标、抽屉栏液态玻璃与页面布局](/assets/wiki/page-settings-v2.png)

### 标语时间

标语时间用于首页顶部展示个性化文案、时间和日期。

可以用于：

- 显示一句固定标语。
- 显示当前时间。
- 显示日期与星期。
- 让导航页更像个人 NAS 首页。

如果截图准备公开发布，建议隐藏过于个人化的标语。

### 全局设置

全局设置用于控制导航页通用行为，例如显示策略、默认交互、同步状态和基础偏好。

常见用途：

- 保存全局显示偏好。
- 控制默认卡片行为。
- 管理设置同步状态。
- 调整面板基础交互。

### 自动地址

自动地址用于批量补全导航卡片的内网地址、外网地址和图标。填写基础地址后，Docker-Panel 会读取 Docker 容器的宿主机映射端口，根据规则自动生成可访问链接，并把结果写入未编辑过的容器卡片。

#### 地址规则

| 配置项 | 说明 |
| --- | --- |
| 内网地址 | 填写 Docker 主机的内网 IP 或主机名，例如 `192.168.1.10`。不需要填写 `http://`、端口和路径。 |
| 外网地址 | 可填写公网 IP 或域名。公网 IP 会使用 `http://` 并自动追加容器端口；域名会使用 `https://`，且不会追加端口。 |

#### 自动补全规则

- **IP 地址**：固定使用 `http://`，并自动追加读取到的宿主机端口。
- **域名地址**：固定使用 `https://`，只使用填写的域名，不自动追加端口。
- **图标获取**：优先使用内网地址获取图标；内网不可用时使用外网地址；仍未匹配时使用图标库或默认图标。
- **未编辑卡片**：普通应用会自动跳过已经手动编辑过的卡片，避免覆盖你的自定义配置。
- **强制更新**：需要一次确认，会覆盖卡片地址和图标，适合批量重新整理所有入口。

#### 操作方式

1. 填写 Docker 主机的内网地址。
2. 如果需要远程访问，再填写外网地址。
3. 点击“应用到未编辑卡片”，系统会为未手动编辑过的卡片补全地址和图标。
4. 第一次安装使用，先点击“强制更新所有卡片”，确认后会覆盖已有地址和图标；后续新入容器卡片会自动写入地址和图标。

![自动地址 / 地址规则与批量补全](/assets/wiki/automatic-address-v2.png)

#### 按节点预设地址

自动地址支持选择本机或任意 Agent 节点分别配置。每个节点都可以预先填写自己的内网地址与外网地址；Agent 在线时也可使用自动检测，检测结果不符合实际网络时可改为手动设置。

节点容器被识别后，会按所属节点的地址预设拼接宿主机映射端口，再自动写入对应导航卡片，不会混用其他服务器的访问地址。

![自动地址 / Agent 节点地址预设](/assets/wiki/agent-node-addresses-v2.png)

### 容器卡片管理

当 Docker 中出现新容器时，面板会根据容器信息创建导航卡片。系统会尽量推断：

| 信息 | 来源 |
| --- | --- |
| 服务名称 | 容器名、镜像名、Docker Labels。 |
| 分组 | 默认分组、Docker Labels、后台分组规则。 |
| 图标 | 图标库、镜像名、服务名、URL 获取、手动上传。 |
| 内网地址 | 宿主机地址和端口映射。 |
| 运行状态 | Docker 容器状态和健康状态。 |

这套能力的目的就是减少手动维护：不用每次新建容器后再找端口、复制地址、创建卡片、找图标和放分组。

### 隐藏容器

不是所有容器都适合出现在导航页。隐藏容器功能可以把基础组件、临时容器、数据库、辅助服务从导航页移除。

适合隐藏：

- 数据库容器。
- 纯后端 API。
- 临时任务容器。
- 不需要点击访问的基础服务。
- 不希望公开展示的服务。

隐藏后仍可在 Docker 面板中管理容器。

可用于：

- 添加非 Docker 网站入口。
- 接入常用后台。

### 面板监控

面板监控是独立于集成服务的实时服务看板。它不会改变已有集成卡片，点击监控卡片也不会跳转服务地址；可直接在面板内查看服务数据并执行常用操作。

<p style="color: var(--vp-c-danger-1); font-weight: 600;">注意：桌面端和移动端的监控卡片新增、删除及尺寸分别管理、独立保存，互不影响；请在对应设备端单独配置。</p>

主要功能：

- 添加、编辑或删除监控卡片，并可选择自定义图标。
- 支持拖动排序、自由调整卡片尺寸，卡片内容区域可独立滑动查看。
- 桌面端和移动端分别保存卡片位置与大小；移动端可在排序状态下实时调整尺寸，保存或刷新后保持布局。
- 页面保持可见时自动刷新服务数据；切换到后台或关闭浏览器后停止刷新，减少不必要的资源占用。
- 卡片透明度跟随全局卡片透明度设置，小尺寸卡片会自动精简内容，避免文字和操作按钮重叠。

目前可用于查看并操作 Emby、qBittorrent、Symedia 和 MoviePilot V2 等服务：例如查看 Emby 播放进度、qBittorrent 下载任务、Symedia 链接与归档任务，以及 MoviePilot V2 的订阅和下载队列。

### 搜索引擎

搜索引擎用于配置 Docker-Panel 内置浏览器的网页搜索服务。

在内置浏览器中输入关键词时，系统会使用这里选择的搜索引擎发起网页搜索，方便在不离开面板的情况下查询资料、文档或服务信息。

使用建议：

- 选择自己日常使用的搜索引擎。

### 导航设置

导航设置仅用于配置快捷栏显示位置，以及访问 Docker-Panel 容器时使用的地址模式。

可配置项：

- **快捷栏位置**：设置快捷入口在导航页中的显示位置。
- **面板容器地址选择**：可选择自动、使用内网地址或使用外网地址。

推荐使用**自动模式**。系统检测到当前处于局域网时使用内网地址；离开局域网后使用外网地址。若自动检测不符合当前网络环境，也可以手动切换为内网或外网地址。

### 分组管理

分组管理用于把服务按用途整理。

推荐分组：

- NAS 监控。
- Docker 服务。
- 下载工具。
- 影音媒体。
- 网址收藏。
- PT 站点。
- 管理后台。

分组不建议过多，否则会降低导航效率。

#### 选项卡片作用

- **新增本机容器卡片加入**：选择本机 Docker 自动识别到新容器时，系统默认写入的导航分组。
- **新增 Agent 节点容器卡片加入**：选择所有 Agent 节点自动识别到新容器时，系统默认写入的导航分组。
- **批量分配**：一次为多个已有服务卡片调整分组，适合首次整理或重构导航页。
- **分组列表**：可拖动调整分组优先级，并使用编辑、删除操作维护分类。

若删除当前选中的默认分组，系统会自动切换为分组列表中的第一个分组，不会重新创建默认分组。

![分组管理 / 服务分类](/assets/wiki/group-management-v2.png)

#### 本机与 Agent 默认分组

可分别设置“新增本机容器卡片加入”和“新增 Agent 节点容器卡片加入”的默认分组。本机 Docker 自动识别的新容器与所有 Agent 节点自动识别的新容器，会各自进入预先选择的分组，方便将本地服务与远程服务器服务按用途整理。

![分组管理 / Agent 节点默认分组](/assets/wiki/agent-default-group-v2.png)

## 后端容器面板

后端容器面板对应 Docker-Panel 后台侧边栏中的“容器管理”“Agent 管理”和“配置管理”区域，用于统一管理本机与远程 Docker 节点、容器、Compose、定时重启、镜像、图标库、代理和更新设置。

### 容器管理

容器管理是集成 Docker 面板的核心。你可以在后台查看所有容器并执行操作。

支持能力：

- 查看容器运行状态。
- 启动容器。
- 停止容器。
- 重启容器。
- 删除容器。
- 查看端口、镜像、运行时间和资源占用。
- 创建更新任务。
- 查看任务进度和日志。

![Docker 工作台 / 容器列表](/assets/wiki/docker-workbench-list-v3.png)

### Compose 项目

Compose 项目页面用于按项目查看和维护服务。

支持能力：

- 查看 Compose 项目列表。
- 查看项目内服务状态。
- 启动、停止、重启项目服务。
- 查看 Compose YAML。
- 可写挂载时保存 YAML。
- 保存后重建项目。

如果只想查看项目，目录可以只读挂载；如果要在线编辑 YAML，需要使用 `:rw`。

::: info 删除 Compose 项目说明
标准 Docker 没有可单独删除的“Compose 项目对象”。在面板中删除 Compose 项目，实际执行的是 `docker compose down`，会移除项目容器和项目网络，但保留 YAML 与项目配置文件。

群晖“项目”列表是 DSM 自己的项目登记，不属于 Docker 标准对象。需要彻底清理时，可选择删除整个项目目录文件；如果只想停止并移除容器，则删除容器并保留项目配置即可。

注意：`DOCKER_COMPOSE_ROOTS: "/vol1/1000/docker"` 必须替换为你主机实际的 Docker 项目根目录，并与对应的目录挂载保持一致；路径错误时，面板无法定位 Compose 文件，也无法删除 Compose 项目文件。

同时建议使用 `/vol1/1000/docker:/vol1/1000/docker:rw` 将 NAS 中的 Compose 项目根目录映射进容器。`rw` 可用于扫描项目、在线编辑 YAML 和重建项目；如果写成 `ro`，面板只能读取，无法编辑 YAML 文件，推荐使用 `rw`。
:::

### 定时重启

定时重启用于为指定容器配置周期性重启。

可自由设置任务执行周期、每日执行时间、时区，以及多个容器之间的重启间隔和就绪等待时间。周期可按每日、每隔几天或每周配置，并可选择需要执行的容器。

适合：

- 长期运行后资源占用升高的服务。
- 需要定期恢复状态的服务。
- 非关键容器的低峰维护。

不建议对数据库、认证、网关等关键服务随意开启定时重启。

![定时重启 / 新建任务与容器选择](/assets/wiki/scheduled-restart-v3.png)

### 镜像管理

镜像管理用于处理 Docker 镜像。

支持能力：

- 查看本机镜像。
- 拉取新镜像。
- 查看拉取任务。
- 删除未使用镜像。
- 清理旧镜像。
- 避免删除正在被容器使用的镜像。

### Agent 节点管理

Agent 用于把远程 VPS、NAS 或其他 Docker 服务器接入 Docker-Panel。每台服务器作为一个独立节点在线连接，面板集中展示节点数量、在线状态，并可实时查看每个节点的 CPU、内存、磁盘占用以及上传下载流量。

接入后，远程节点的容器会同步到统一工作台与导航页。你可以按节点查看容器状态、资源占用、端口和日志，并执行容器、Compose、镜像、更新等日常管理操作；节点离线时，对应卡片会显示节点离线状态，避免误操作。

节点支持添加、重命名、编辑地址预设、吊销连接和删除。添加节点时使用面板生成的接入信息完成注册，不需要把远程 Docker Socket 暴露到公网。

![Agent 管理 / 多服务器节点总览](/assets/wiki/agent-nodes-v4.png)

常用操作：

- **搜索节点**：按 Agent 名称或地址快速筛选。
- **切换视图**：点击搜索框右侧的列表 / 网格图标，在列表与卡片模式之间切换。
- **拖动排序**：先清空搜索，点击搜索框右侧的排序图标进入排序模式，拖动节点调整顺序，再次点击该图标保存。节点顺序也会同步到面板监控中的 DP 节点卡片。
- **切换与维护**：点击“切换”选择要管理的在线节点；“编辑”用于修改节点配置。“吊销”会断开连接，需重新接入才能恢复；“删除”会移除节点及其任务记录。

点击节点卡片空白处或“详情”可展开节点详情，查看在线状态、运行时间、系统架构、Agent 版本、内存与磁盘用量、实时和累计上传下载，以及 CPU、内存、磁盘和网络资源曲线。底部节点栏可直接切换查看其他节点，点击右上角关闭按钮返回总览。

![Agent 管理 / 展开节点详情与实时资源曲线](/assets/wiki/agent-node-detail-v1.png)

### SSH 终端

SSH 终端用于在 Docker-Panel 内集中管理主机 SSH 连接。无需离开面板，即可建立终端会话、执行命令并查看远程主机文件，适合处理容器之外的系统维护操作。

使用方式：

- 在“连接配置”中填写主机地址、端口、用户名和认证信息，可先使用“测试连接”确认配置可用。
- 保存常用主机后，可从左侧连接列表快速发起新的终端会话；本机 Docker 与已保存 SSH 主机均可单独管理。
- 终端区域支持命令交互；底部文件区域可在连接成功后浏览远程文件，便于在维护时同时处理命令和文件。
- 侧栏会展示主机的 CPU、内存、存储、网络流量等概览信息，方便确认当前连接主机的基本状态。

![SSH 终端 / 连接与文件管理](/assets/wiki/ssh-terminal-v2.png)

### 挂载检查

挂载检查用于确认面板容器能否访问宿主机目录及 Compose YAML 文件，帮助排查项目无法读取、在线编辑或删除文件等问题。入口位于后台“配置管理 → 挂载”。

页面内容：

- **挂载概览**：查看挂载点数量、当前可访问数量和 YAML 异常数量。
- **面板容器挂载**：对照宿主机路径与容器内路径，确认挂载类型、是否可访问，以及读写或只读状态。
- **Compose YAML 路径检查**：查看项目原始 YAML 路径、面板实际读取路径及匹配的挂载，确认文件是否可读。
- **容器 YAML 诊断**：按容器查看缺少挂载、权限不足、文件不存在或缺少 YAML 标签等状态，可搜索容器、项目和 YAML 路径。

使用时先查看顶部检查结果，再定位异常项目。缺少挂载时，按页面提示将项目父目录映射进面板容器；权限不足时，检查宿主机目录权限及挂载的读写设置。修改部署配置并重新创建面板容器后，点击“刷新”重新检查。

::: tip Compose 目录与权限
`DOCKER_COMPOSE_ROOTS` 应填写实际的 Compose 项目根目录，并配合对应目录挂载。例如群晖使用 `/volume1/docker` 时，可设置 `DOCKER_COMPOSE_ROOTS: "/volume1/docker"`，并挂载 `/volume1/docker:/volume1/docker:rw`。请按主机实际路径修改；只读挂载可用于读取，在线编辑和删除项目文件需要读写权限。

挂载检查只负责诊断，不会自动修改挂载或修复文件。非 Compose 容器没有可检查的 Compose YAML，不代表挂载异常。
:::

![挂载检查 / 面板挂载与 Compose YAML 路径诊断](/assets/wiki/mount-inspection-v1.png)

图标库适合集中维护常用服务图标，例如媒体服务、下载工具、NAS 工具、代理服务、监控服务和自建应用。

### 代理设置

代理设置用于 Docker-Panel 的镜像版本检测、Telegram 消息与机器人交互，也用于 NAS Docker 原生拉取失败后的 DP 兜底镜像下载。

填写方式：

- 普通代理：`http://host:port`
- 带认证代理：`http://user:password@host:port`
- 留空：Docker 更新检测、Telegram 与兜底下载均使用直连。

企业微信继续使用消息通知中心内单独配置的“微信代理 URL”，不使用此处代理。

保存后可点击“测试代理”，确认当前地址可用于镜像版本检测与 Telegram 请求；代理不可用时不会写入升级日志。

#### 自定义镜像源与 DP 兜底拉取

当 NAS 的 Docker 原生拉取因网络问题失败时，开启“启用 DP 兜底拉取”后，面板会按列表从上到下依次尝试自定义 Docker Hub 镜像源下载镜像。

- 每个镜像源可单独命名、调整顺序、测试或删除。
- “新增镜像源”可添加自建或公共镜像地址；“恢复默认”会还原内置镜像源列表。
- “并行测试全部”可快速检查所有镜像源的当前连通性，建议先测试再保存。
- 兜底拉取仅在 Docker 原生拉取失败时启用，不会替代宿主机 Docker 的正常拉取流程。

![代理设置 / 更新检测、Telegram 与镜像源兜底拉取](/assets/wiki/proxy-settings-v4.png)

### Docker 设置

Docker 设置用于控制容器的更新检查、镜像自动升级与旧镜像清理。

#### 更新检查跳过

勾选后的容器不会参与“待更新”扫描，也不会自动进行镜像比较。适合不希望频繁检查或暂不升级的服务。

![Docker 设置 / 更新检查跳过](/assets/wiki/update-check-skip-v2.png)

#### 镜像自动升级

可选择需要自动升级的容器。系统检测到新镜像后会自动创建升级任务，并按任务顺序执行；升级失败时会保留并恢复旧容器，避免服务直接中断。

![Docker 设置 / 镜像自动升级](/assets/wiki/automatic-image-upgrade-v2.png)

#### 容器自动恢复

容器自动恢复用于监测已勾选容器的异常停止、健康检查失败和资源持续超限情况，并在满足条件时自动重启容器。

选择列表会显示当前节点的全部容器，支持按名称或镜像搜索和全选。普通管理员登录时可查看全部容器；使用 B 密码进入安全模式后，安全中心已设置隐藏的容器不会显示在列表中。

可按需开启异常停止与健康检查恢复、CPU 持续超限和内存持续超限，并设置 CPU/内存阈值、连续超限时间、最大尝试次数及失败冷却时间。系统只会对已选择的容器执行恢复；面板自身和手动停止的容器不会触发自动恢复。

![Docker 设置 / 容器自动恢复](/assets/wiki/container-auto-recovery-v3.png)

#### 旧镜像清理

开启后，容器成功更新并重启完成时会清理本次升级前的旧镜像。若旧镜像仍被其他容器使用，系统会自动保留，不会删除正在使用的镜像。

### 安全中心

安全中心对应后台“安全模式”，用于配置隐藏访问、受保护容器及受控清理范围。可在页面右上角启用或停用；停用时保留配置，但 B / C 密码登录暂不生效。

#### 密码与隐藏访问

- **A 密码**：当前管理员密码，用于正常登录，以及首次设置、更改或重置 B / C 密码时验证身份。
- **B 密码**：使用同一用户名和 B 密码登录隐藏面板。勾选的受保护容器及其关联镜像、Compose、统计、详情和控制内容会隐藏；正常管理员使用 A 密码登录时仍可查看完整资源。
- **C 密码**：在登录页输入时仍提示普通密码错误，但会累计连续命中次数。连续正确输入达到配置阈值后，创建受控清理任务；输入 A、B 或其他错误密码会清零计数。

#### 受保护容器与清理范围

在“受保护容器”中选择需要保护的容器，系统会同时保护其当前使用的镜像。再按需配置“销毁节点与业务资源”和“Compose 允许目录”，逐项核对目标节点、业务容器、镜像、无端点的自定义网络及允许目录内的 Compose 项目文件夹。

Compose 允许目录每行填写一个实际根目录，只允许清理这些目录内、由 Docker 已发现的 Compose 配置定位到的项目文件夹，不接受任意文件路径。配置完成后保存，并按页面提示验证 A 密码。

::: danger 清理任务不可取消
C 密码达到连续命中阈值后，创建的清理任务不可取消。启用前请确认目标资源与目录边界，并提前备份重要配置和数据，不要在生产环境随意测试。

任务不会删除 Docker 卷、Docker-Panel 容器、面板数据库、Docker 根目录或操作系统文件；但允许目录内的项目文件夹可能包含业务数据，清理前务必核对。
:::

![安全中心 / 隐藏访问、受保护容器与受控清理范围](/assets/wiki/security-center-v1.png)

### 消息通知

消息通知用于把面板的重要事件主动发送到 Telegram 或企业微信。配置完成后，可在不打开面板的情况下及时获知更新检查、定时任务、容器状态和 Agent 节点变化。

![消息通知 / 渠道设置](/assets/wiki/message-notification-channels-v2.png)

#### 配置渠道

进入“消息通知”后，先在“渠道设置”中启用需要使用的通知渠道：

- **Telegram**：填写 Bot Token 与接收消息的 Chat ID，保存后点击“测试通知”确认机器人可正常发送消息；需要时可同步机器人菜单。
- **企业微信**：填写企业 ID、应用 ID、应用 Secret、Token 和 EncodingAESKey，并填写企业微信后台可访问的回调外网地址与自定义后缀。保存后可执行“回调自检”和“测试通知”。

企业微信回调地址必须可从公网访问，并使用与企业主体相同或关联的备案域名；`127.0.0.1`、`localhost` 和内网 IP 无法通过企业微信回调验证。

#### 设置通知规则

切换到“通知规则”，按事件和渠道勾选需要接收的通知后保存即可。可单独选择 Telegram、企业微信或同时发送到两个渠道。当前可通知的事件包括：

- 自动更新与检测错误
- 定时重启结果
- 容器异常与容器恢复
- Agent 上线或离线
- Agent 到期通知
- 发现可用更新

**Agent 到期提醒**：进入到期前 7 天内，每天 08:00 提醒；进入到期前 3 天内，每天 08:00 和 20:00 提醒。可在该事件对应的 Telegram、企业微信列分别勾选，点击“保存规则”后生效；接收渠道需先完成配置并启用。

![消息通知 / 通知规则与 Agent 到期提醒](/assets/wiki/message-notification-rules-v3.png)

#### 查看发送记录

“发送记录”会保留每次通知的发送时间、目标渠道和结果。测试通知或实际事件未收到消息时，可先查看该记录，再检查渠道凭据、网络连通性和已勾选的通知规则。

### 底部与系统操作

对应后台底部的明暗模式、系统设置和退出登录，是日常使用时最常用的基础操作。

#### 明亮模式

明亮模式用于切换界面显示风格。根据使用环境选择明亮或深色显示，方便白天、夜间或大屏展示时查看。

#### 系统设置

系统设置用于进入面板基础配置区域，处理账户、安全、全局偏好和运行参数等设置。

#### 退出登录

退出登录会结束当前后台会话。公共设备或共享电脑使用后建议主动退出。

#### 备份与维护

备份与恢复用于导出和恢复 Docker-Panel 的导航配置与 Agent 节点信息，适合迁移面板、重建环境或在升级前保留当前配置。

导出备份包含：

- 系统设置、导航卡片、分组与集成服务配置。
- Agent 节点信息与凭据校验信息。
- 本地上传的图标、背景等资源。

恢复到**同一面板地址**后，已接入的 Agent 节点可自动重连，不需要逐台服务器重新注册。恢复备份不会覆盖管理员账号和密码。

迁移或升级前建议先导出备份；需要恢复时，在目标面板选择备份文件即可还原导航、节点和相关配置。

![备份与恢复 / 导出与恢复](/assets/wiki/backup-restore-v2.png)
